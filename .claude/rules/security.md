# Security rules

These apply in every session and to every file.

- **Secrets.** Never read, print, create, or commit `.env`, `.env.local`, or any other file that holds credentials. `.env.example` is the only env file agents touch. Never put an API key, token, password, or connection string with a password in code, docs, commits, logs, or output you echo back.
- **Data.** Use synthetic data only: invented names, made-up emails such as `visitor@example.com`, generated values. Never put a real visitor's message, email, or IP address into fixtures, tests, docs, or prompts. When you inspect production data at the owner's request, report counts and statuses, never message content or email addresses.
- **Hosting accounts.** Agents never create, delete, or reconfigure Vercel or Render projects, Neon databases, Resend keys or domains, GitHub tokens, UptimeRobot monitors, DNS records, or environment variables on those platforms. Write out the steps or commands for the owner to run instead (the runbook is `../portfolio-implementation-plan.md` §8).
- **Production.** Live testing and browser automation target `localhost` by default. Checks against the production site happen only when the owner asks, and are read-only: page loads, `GET` requests, and the health endpoint. Never submit the production contact form or post test page views to production.
- **The private parent folder.** This repository sits inside a private CV folder. Read only the two master plans there (`../portfolio-implementation-plan.md`, `../cv-portfolio-content-plan.md`) and owner-approved text in `../portfolio-content/`. Never read, quote, or copy any other file from the parent folder, and never move a file from it into this repository except reviewed content and the public CV PDF.
- **Other codebases.** Never copy text, code, names, identifiers, or screenshots from an employer's or any other private codebase into this repository, even to illustrate a case study. Case-study diagrams are drawn fresh with generic labels. `.local/` is machine-local: never commit it or quote it in committed files.
- **Disclosure.** Tier C content (see `docs/product/product-guide.md`) never enters a file, commit message, branch name, pull request, or issue. `/create-pr` runs the scrub against `.local/scrub-patterns.txt`; never print that file's patterns or the lines they match.
- **Dependencies.** Pin dependency and image versions; never use `latest` tags or open version ranges. Prefer libraries already in use over new ones; a new dependency is justified in the plan (Non-Negotiable 8).
- **Guardrails.** Never skip git hooks (`--no-verify`) or disable permission checks. Change permission rules or hooks in `.claude/settings.json` only when the owner asks for that change.
