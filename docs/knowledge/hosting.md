# Hosting

Facts about Vercel, Render, and Neon observed on this site's own projects. Versions and defaults are as of the date in each entry.

## Vercel

### Vercel ignored `packageManager` and picked its own pnpm
- **Rule / Behavior**: For the project with Root Directory `frontend` and `ENABLE_EXPERIMENTAL_COREPACK=1`, Vercel's build warned "Could not enable corepack because package.json is missing "packageManager" property" although `frontend/package.json` declares `pnpm@11.0.9`, then installed with a pnpm that ignored the lockfile ("Ignoring not compatible lockfile") and failed with `ERR_PNPM_META_FETCH_FAIL … Value of "this" must be of type URLSearchParams`. With a version 9 lockfile, `vercel build` logs that the lockfile "may be generated by pnpm@9.x, pnpm@10.x, pnpm@11.x, or pnpm@12.x" and chooses "pnpm@10.x based on project creation date". Pinning pnpm in the commands themselves (`npx --yes pnpm@11.0.9 install --frozen-lockfile`, `npx --yes pnpm@11.0.9 run build`) installs with pnpm 11.0.9 whatever Vercel detects.
- **Source**: the first production build's log on Vercel; `frontend/vercel.json`
- **Verified**: the first deployment failed and the next one, with the pinned commands, succeeded; a local `vercel build --prod` with Vercel CLI 66.2.0 logged the detection lines and "Done in 1.6s using pnpm v11.0.9"; 2026-11-23
- **Discovered in**: PF-013

### `engines.node` overrides the project's Node.js Version setting
- **Rule / Behavior**: When `package.json` has `engines.node` (`^24.22.0`), Vercel ignores the Node.js Version in the Project Settings (26.x) and uses the matching major version (24.x), with a warning that names both.
- **Source**: `frontend/package.json`; `vercel build --prod` output
- **Verified**: local `vercel build --prod` with Vercel CLI 66.2.0; 2026-11-23
- **Discovered in**: PF-013

### The Vercel CLI runs from the repository root for a project with a Root Directory
- **Rule / Behavior**: With `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID` set, `vercel pull --yes --environment=production` run from the repository root writes `.vercel/project.json` (with `rootDirectory: frontend` and the dashboard build settings) and `.vercel/.env.production.local`. `vercel build --prod` from the root then builds `frontend/` with the `installCommand` and `buildCommand` from `frontend/vercel.json` when the dashboard commands are blank, writes `.vercel/output` (static files plus the SPA rewrite route) at the root, and also leaves files under `frontend/.vercel/static-build/`, which Prettier would check unless ignored.
- **Source**: the `deploy` job in `.github/workflows/frontend.yml`; `frontend/.prettierignore`
- **Verified**: local `vercel pull` and `vercel build --prod` with Vercel CLI 66.2.0, the dashboard commands blanked in the local `.vercel/project.json`; 2026-11-23
- **Discovered in**: PF-013
